# Data Dictionary — Quality Intelligence Platform

## 1. Purpose

This document describes the canonical fields produced after
standardizing the heterogeneous QHC Excel audit sheets.

The canonical schema represents the standardized ingestion layer.

It does not yet represent the final PostgreSQL analytical model.

---

# 2. Dataset Granularity

Current standardized dataset granularity:

One row = one ISO control / clause for one audited account sheet.

A row does not necessarily mean that the corresponding control
has already been evaluated.

The current campaign is still in progress.

---

# 3. Technical Traceability Fields

## source_file

**Type expected:** string

**Description:**  
Name of the Excel workbook from which the row was extracted.

**Example:**

`QHC_ISO9001_Audits_FY27.xlsx`

**Nullable:** No

**Origin:** Generated by the ingestion process.

**Purpose:** Traceability.

---

## source_sheet

**Type expected:** string

**Description:**  
Name of the Excel sheet from which the row was extracted.

In the current workbook, audit sheets correspond to accounts.

**Example:**

`RAM`

`Servier`

`Min. Intérieur`

**Nullable:** No

**Origin:** Excel sheet name.

**Important:**  
During Phase 1, `source_sheet` is used to identify the source account.

The final data model may later introduce a dedicated account identifier.

---

# 4. Source Row

## source_row_number

**Type expected:** integer

**Description:**  
Original checklist row number coming from the Excel `N°` column.

**Nullable:** Potentially

**Important:**  
This field is not a reliable business primary key.

It is preserved mainly for source traceability.

---

# 5. ISO Referential Fields

## clause_iso

**Type expected:** string

**Description:**  
ISO 9001 clause associated with the control.

**Nullable:** Normally no for a checklist control.

---

## intitule_iso

**Type expected:** string

**Description:**  
Official ISO 9001 title associated with the clause.

**Source variants mapped:**

- `Intitulé ISO`
- `Intitulé Officiel ISO 9001:2015`

---

## libelle_terrain

**Type expected:** string

**Description:**  
Operational/business wording used to make the ISO requirement
more understandable during the audit.

---

## controle_attendu

**Type expected:** string

**Description:**  
Description of what the auditor is expected to verify.

**Source field:**

`Ce qu'il faut contrôler`

---

## categorie_scope

**Type expected:** categorical string

**Description:**  
Defines the applicability scope of the control.

**Currently observed values:**

- `Compte`
- `Entité`
- `Entité et Compte`

**Important:**  
This field is different from `categorie_finding`.

---

## reference_edge

**Type expected:** string

**Description:**  
Reference to the corresponding DXC EDGE requirement or control.

**Source field:**

`Référence DXC EDGE`

---

## preuves_attendues

**Type expected:** string

**Description:**  
Expected evidence that can demonstrate compliance with the control.

---

# 6. Auditor Assessment

## constat_auditeur

**Type expected:** text

**Description:**  
Observation or assessment written by the auditor for the control.

**Nullable:** Yes

A missing value may be legitimate when the audit has not yet reached
the corresponding control.

---

## niveau_maturite

**Type expected:** categorical string

**Description:**  
Qualitative maturity level attributed to the control.

**Canonical values currently envisaged:**

- `Non en place/Elémentaire`
- `Partiellement en place/Réactif`
- `Largement en place/Stable`
- `Totalement en place/Proactif`

**Known source variants include:**

- `Partiellement`
- `Largement en place`
- `Totalement en place / Proactif`

These variants will later be normalized.

`⏳ Non audité` should not be treated as a true maturity level.

---

## score_maturite

**Type expected:** integer

**Expected business domain:** 1 to 5

**Values currently observed:** 1 to 4

**Description:**  
Numerical maturity score assigned to an evaluated control.

**Nullable:** Yes

A NULL may be legitimate when the control has not yet been evaluated.

---

# 7. Findings

## categorie_finding

**Type expected:** categorical string

**Currently observed values:**

- `NC Mineure`
- `NC Majeure`
- `Observation`
- `Bonne Pratique`

**Description:**  
Classification of the audit finding associated with the control.

**Nullable:** Yes

A control does not necessarily generate a finding.

**Important:**  
`Bonne Pratique` must not be treated as a negative non-conformity
in the corresponding KPIs.

---

# 8. Corrective Actions

## action_corrective

**Type expected:** text

**Description:**  
Corrective action defined in response to an audit finding.

**Nullable:** Yes

Not every control or finding necessarily requires a corrective action.

---

## responsable_action

**Type expected:** string

**Description:**  
Person or role responsible for the corrective action.

**Nullable:** Conditional

If an action corrective exists, this field may become mandatory
according to the final Data Quality rules.

---

## date_debut

**Type expected:** date

**Description:**  
Canonical start date of the corrective action.

**Source variants mapped:**

- `Date de début`
- `Date de réalisation prévisionnelle`
- `Date de réalisation previsionelle`

**Nullable:** Yes

The current audit campaign is still being populated.

---

## date_cloture

**Type expected:** date

**Description:**  
Canonical closure date used by the project.

**Source variants mapped:**

- `Date de clôture`
- `Délai prévu`
- `Délai Prévu`
- `Délai de clôture`

**Nullable:** Yes

These mappings follow the business convention validated for the project.

---

## statut_action

**Type expected:** categorical string

**Description:**  
Current status of the corrective action.

**Values currently observed:**

- `Ouvert`
- `En cours`

Additional statuses such as `Clôturé` may appear later.

**Nullable:** Conditional

A NULL can be legitimate when no corrective action exists.

---

## age_jours

**Type expected:** integer

**Description:**  
Age of an open corrective action expressed in days.

For an action that is not closed:

`age_jours = current_date - date_debut`

When the action becomes `Clôturé`, its age must stop increasing.

**Nullable:** Conditional

**Data Quality:**  
Values such as `#REF!` are invalid.

---

## indicateur_age

**Type expected:** categorical string

**Description:**  
Deterministic classification derived from `age_jours`.

**Current business rule:**

- 0–30 days → `Normal`
- 31–60 days → `Alerte`
- 61–90 days → `Critique`
- > 90 days → `Escalade management`

The platform should recalculate this value rather than relying
on Excel formulas.

---

# 9. Supporting Information

## evidence

**Type expected:** text / string

**Description:**  
Evidence associated with the audit control or corrective action.

**Nullable:** Yes

---

## commentaires

**Type expected:** text

**Description:**  
Additional comments associated with the control, finding or action.

**Nullable:** Yes

---

# 10. Audit Status

The account audit status is not directly represented by one of the
canonical Excel columns above.

The platform must maintain separate concepts:

- `statut_propose`
- `statut_valide`
- `date_validation`
- `valide_par`

The proposed status is generated by a deterministic provisional rule.

The validated status is confirmed or modified manually by the
Quality team and represents the official business status.

---

# 11. Current Dataset Characteristics

At the current Phase 1 snapshot:

- Audit account sheets: 20
- Checklist rows per account: 45
- Standardized rows: 900
- Standardized columns: 23
- Canonical mapped columns: 21
- Technical traceability columns: 2

The current dataset is not final.

The audit campaign is still in progress and data completeness
is expected to evolve over time.
